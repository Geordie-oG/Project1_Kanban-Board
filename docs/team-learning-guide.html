01 / Team Code Guide

What does our application do?

It gives a team one place to organize tasks, move work through a three-stage workflow, and review progress from live data.

Short answer

Create, edit, delete, assign, search, filter, and move tasks. The app saves tasks and categories in the browser, then derives the Dashboard from the same shared task state.

The main product areas

Kanban Board

Three columns: TO DO, DOING, and DONE. Each task shows its category, dates, responsible person, and available actions.

Dashboard

Five summary cards and three charts describe status, categories, overdue work, and completion performance using current task data.

03 / React Features

Lazy-loaded Dashboard

The Dashboard bundle is requested when its route is opened.

Optional performance feature

This is a useful extra for demonstrating code splitting. The Kanban screen can render first while the Dashboard remains a separate chunk.

const DashboardPage = lazy( () => import('./pages/DashboardPage.jsx') ) <Suspense fallback={<RouteLoader />}> <Routes>...</Routes> </Suspense>

What happens

Kanban ready
CLICK DASHBOARD
request chunk
WAIT IF NEEDED
show loader
SHOW PAGE

Keep or simplify?

Keep it when

The team can explain lazy, Suspense, and the loading fallback, and can demonstrate both routes.

Simplify when

The project needs the smallest possible codebase. Use a normal Dashboard import and preserve the `/dashboard` route.

15-second answer

“React lazy loading requests the Dashboard code when that route opens. Suspense gives the user temporary feedback while it loads.”

04 / Accessibility

Keyboard focus management

Because React changes screens without a full document refresh, focus is deliberately returned to meaningful content.

Two focus paths

After route change

App.jsx scrolls to the top, waits for rendering, finds the new page H1, and focuses it. A MutationObserver handles a heading that appears after lazy loading.

After task movement

KanbanPage.jsx focuses the task card after it moves and announces the new status in a live region.

Technical words

ToolMeaning here
requestAnimationFrameWaits until the browser is ready for the next rendered frame.
MutationObserverWatches for the lazy Dashboard heading to appear.
tabindex="-1"Allows code to focus a heading without adding it to normal Tab order.

Keyboard test

  1. Use Tab and Enter to move between Board and Dashboard.
  2. Confirm the new page heading receives focus.
  3. Move a task and confirm focus follows the moved card.
  4. Listen for the status announcement if assistive technology is available.

15-second answer

“Route focus keeps keyboard users oriented after navigation, and task focus keeps their place after a card moves.”

05 / Modal Accessibility

Accessible task editing

The create and edit form behaves like a keyboard-friendly dialog.

PREPARE

FOCUS

CONTAIN
Tab loop

What TaskForm.jsx handles

BehaviorImplementation
Dialog semanticsrole="dialog", aria-modal, labelled heading, and close button.
Initial focusThe title input is focused when the form opens.
Keyboard controlEscape closes; Tab and Shift+Tab wrap within the dialog.
ValidationThe first invalid field receives focus after submission.
Focus restorationThe element that opened the form receives focus after closing.

Without this handling

A keyboard user could reach controls behind the modal, miss the field needing correction, or lose their position when the form closes.

Fast test

  1. Open New task and confirm the title field is focused.
  2. Press Shift+Tab and confirm focus wraps to the last control.
  3. Submit invalid data and confirm an error field receives focus.
  4. Press Escape and confirm focus returns to New task.

06 / Reliability

Defensive Local Storage validation

Browser storage can be missing, old, malformed, or manually edited. The app repairs data before trusting it.

STORED DATA
may be invalid
SAFE PARSE
try/catch
HYDRATE
normalize fields
VALID STATE
render safely

Where the protection lives

FileResponsibility
src/utils/storage.jsVersioned keys and safe JSON read/write operations.
src/utils/taskHydration.jsSanitizes task fields, dates, IDs, status values, and category casing.
src/context/TaskContext.jsxLoads once, hydrates data, then persists task and category changes.

Examples of repair

ProblemApp response
Broken JSON or wrong typeUse fallback data instead of crashing.
Unknown status or invalid dateUse a safe default or empty date.
Duplicate or missing task IDCreate a unique ID.
Completion date on unfinished taskClear it unless the task is DONE.

Recommendation

Keep the safe parsing and valid-array checks. They protect the required persistence feature and are covered by task hydration tests.

07 / Board and Dashboard Logic

Required behavior to explain

The visual interface is backed by small, testable rules.

Movement rules

Entering DONE

When a task moves into DONE, the app records today as completeDate.

Leaving DONE

When a task leaves DONE, the completion date is cleared so the record stays honest.

Dashboard calculations

MetricRule

TO DO / DOING / DONETasks grouped by canonical status.
OverdueDue date is before today and status is not DONE.
EarlyCompletion date is before due date.
